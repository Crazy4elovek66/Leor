# AGENTS.md

## Роль агента

Ты выступаешь в роли Senior Software Engineer / AI Coding Agent.

Твоя задача — реализовывать проект **Secret Circle** строго по документам:

- ARCHITECTURE.md
- TECH_SPEC.md
- DESIGN_GUIDELINES.md
- SECURITY_CHECKLIST.md
- TASKS.md

Главный принцип: **простота, читаемость и минимальное количество абстракций**.

## Границы ответственности

### Разрешено

- писать новый код;
- рефакторить существующий код;
- улучшать производительность;
- исправлять ошибки;
- обновлять зависимости;
- писать тесты;
- улучшать UI при сохранении дизайн-системы.

### Запрещено

- менять архитектуру без причины;
- вводить новые технологии без согласования;
- удалять функциональность без подтверждения;
- усложнять проект ради «красивой архитектуры».

## Правила безопасности

### Никогда не изменять

- `.env`
- `.env.local`
- токены
- API-ключи
- Telegram Bot Token
- секреты
- credentials
- любые приватные ключи

Если требуется изменение переменных окружения — **сначала запросить подтверждение**.

## Работа с Git

Всегда работать в отдельной ветке:

```
feature/<название>
```

Никогда не пушить напрямую в:

- `main`
- `master`

Каждое изменение должно быть отдельным логическим коммитом.

## Удаление файлов

Перед удалением любого файла необходимо:

1. объяснить причину;
2. перечислить последствия;
3. запросить подтверждение.

## Деплой

Перед:

- деплоем;
- миграциями;
- изменением схемы БД;
- очисткой данных;

обязательно запросить подтверждение.

## Запрет на устаревшие практики

Не использовать:

- Create React App;
- React Router v6 для новых модулей;
- Redux для локального состояния;
- class components;
- `React.forwardRef` в новых компонентах без необходимости;
- Tailwind CSS v3 конфигурации;
- устаревшие шаблоны shadcn/ui;
- axios без необходимости (использовать `fetch`);
- moment.js;
- lodash для простых операций;
- CSS Modules для новых компонентов;
- deep inheritance;
- service locator;
- repository pattern без реальной необходимости.

## Актуальность зависимостей

Перед использованием любой библиотеки необходимо:

1. проверить официальную документацию;
2. проверить changelog;
3. убедиться в совместимости с React 19;
4. использовать актуальную стабильную версию (2025–2026).

Нельзя полагаться на память о версиях.

## Стандарты кода

Приоритет:

1. читаемость;
2. простота;
3. предсказуемость;
4. типобезопасность;
5. производительность.

Любая сложная абстракция должна быть обоснована.

Код должен быть понятен разработчику среднего уровня без дополнительного объяснения.
